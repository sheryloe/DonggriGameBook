## 1. 페이로드 — 패키지가 아니라 런타임 다운로드

### 1-0. 먼저 사실관계

배포 경로를 실측한 결과, 처음 세운 전제가 틀렸다. 기록해 둔다.

| 대상 | 크기 | 성격 |
|---|---:|---|
| `donggrolgamebook.ait` | **11.3 MB** | **실제 토스 배포 패키지** |
| `dist/toss` | 59.7 MB | 90 MiB 게이트가 재는 대상 (`audit-wave11-toss-save.mjs:9,325`) — **통과 중** |
| `dist/part1` | 99.5 MB | 웹 빌드. 게이트 대상이 아니다 |

- AIT 안에는 소스맵·이미지의 **파일명 참조만** 있고 바이트가 없다. PNG 매직 0개, IHDR 청크 0개, `sourceMappingURL` 0개로 확인했다.
- **`dist/toss`에는 게임 미디어가 하나도 없다.** webp 0, mp3 0.
- `packages/app-runtime/src/assets/runtimeAssetUrls.ts:38`이 `https://assets.<도메인>`으로 해석한다. **미디어는 플레이 중 CDN에서 내려받는다.**

따라서 **사용자가 치르는 비용은 패키지 크기가 아니라 플레이 중 네트워크 다운로드다.** 최적화는 여기를 겨눈다.

### 1-1. 런타임 다운로드 (실효 대상)

| 항목 | 현재 | 조치 |
|---|---:|---|

첫 챕터 진입까지 받아야 하는 양을 기준으로 잡는다. 전량이 아니라 **첫 화면까지의 바이트**가 이탈을 만든다.

## 2. 아트 — 게임 스타일 전환

### 2-1. 실사가 나오는 이유

`PROMPT_PACK_IMAGE_VIDEO.md`가 모든 캐릭터 템플릿에 `documentary disaster realism`, `documentary lighting`, `realistic proportions`를 박아 놓았다. `documentary`는 "실제 사건을 기록한 것처럼"이라는 뜻이다. 명세대로 나온 결과다.

### 2-2. 교체할 키워드

```
빼기: documentary disaster realism, documentary lighting,
      realistic proportions, photorealistic, candid, editorial

넣기: painted key art, digital painting, visible brushwork,
      stylised realism, strong directional key light, rim light,
      limited palette with one accent, high contrast,
      readable silhouette, game splash art
```

유지: `no anime proportions`, `no recognizable brands`, `no tactical cosplay`, `no superhero pose`

**토스 = 작은 화면.** 얼굴 디테일이 아니라 **실루엣과 의상 형태**로 인물이 구분되어야 한다. 이것이 스타일 전환의 실용적 이유이기도 하다 — 실사는 축소하면 뭉개지고, 회화체는 축소해도 읽힌다.

### 2-3. 반복 문제

**355개 이벤트가 38장을 돌려 쓴다.** 윤해인 대사 15회에 같은 사진 15번.

해법은 이미 검증했다. **배경 × 누끼 흉상 조합**이면 장수를 곱한다. 흉상 10장 + 배경 38장이면 조합이 380가지다. 신규 배경 없이 변주가 생긴다.

### 2-4. 생성 파이프라인 (검증 완료)

```
codex exec -m gpt-5.6-terra -c model_reasoning_effort=high -s read-only
  → #00ff00 크로마키로 생성
  → scripts/make-bust-cutout.ps1  (플러드필 누끼 + 디스필 + 다운스케일)
  → CSS filter로 장면 톤에 정합
```

안보경 흉상 실측: 1024×1536 생성 → 720×1080 누끼 / 1.4 MB, 배경 48.1% 제거, 녹색 번짐 4,359px 보정, 네 모서리 알파 0, 얼굴 `R211 G165 B141`(초록 오염 없음).

Gemini 대비: **워터마크 없음**, 크로마키 완전 평탄(`R1 G250 B5`), 명세 준수, 사람 손 불필요.

### 2-5. 톤 정합

배경은 게임이 `rgba(5,7,8,0.7→0.95)`로 누르는데 인물만 그대로라 혼자 쨍하다.

```css
.npc-portrait-container.is-cutout .npc-portrait {
  filter: brightness(0.74) saturate(0.82);
  mask-image: linear-gradient(to bottom, #000 88%, transparent 100%);
}
```

2-2의 스타일 전환이 적용되면 이 격차는 상당 부분 자연히 줄어든다. 회화체는 애초에 대비가 눌려 있다.

## 3. SVG / 비트맵 경계

**이미 증거가 있다. SVG 124장이 전부 합쳐 0.5 MB다.** WebP 46장이 26.5 MB인 것과 비교하면 50배 차이다. 토스 페이로드에서 SVG로 갈 수 있는 것을 비트맵으로 만드는 건 그대로 손해다.

| SVG로 만든다 | 비트맵(codex)으로 만든다 |
|---|---|
| UI 프레임·패널·구분선 | 장면 배경 |
| 아이콘 (아이템, 스탯, 퀘스트 표식) | NPC 흉상·초상 |
| 스탯 게이지·타이머·마감 표시 | 보스 아트 |
| 노드 지도 / 이동 경로 | 챕터 포스터 |
| 챕터 타이틀 카드 테두리 | 시네마틱 스틸 |
| 로딩·전환 효과 | |

기준: **선과 도형으로 설명되면 SVG, 질감과 빛으로 설명되면 비트맵.**

SVG는 추가로 화면 크기에 무관하고, 다크/라이트 대응이 코드 한 줄이며, 색을 런타임에 바꿀 수 있다. 스탯이 위험 구간에 들어갈 때 게이지가 붉어지는 연출은 SVG여야 공짜다.

## 4. 구조 — 놀이의 질

### 4-1. 고아 이벤트 27개

작성됐지만 **어떤 노드에도 걸려 있지 않고 어떤 선택도 가리키지 않는** 이벤트다. CH01 13개, CH02 8개, CH03 1개, CH04 2개, CH05 3개.

챕터별로 하나씩 판정한다 — 연결하거나 지운다. 남겨 두면 분량 통계만 부풀리고 플레이어는 영원히 못 본다.

### 4-1a. 미리보기가 거짓말을 한다 ← 밀도보다 먼저

측정: `scripts/audit-part1-choice-truth.mjs`

**자원 변화를 명시한 선택지 263개 중 183개(70%)가 실제로 일어나지 않는 일을 약속한다.**

| 챕터 | 거짓 / 검사 |
|---|---|
| CH01 | 54 / 75 (72%) |
| CH02 | 47 / 64 (73%) |
| CH03 | 35 / 54 (65%) |
| CH04 | 22 / 31 (71%) |
| CH05 | 25 / 39 (64%) |

원인은 라벨에서 고쳤던 것과 같은 병이다. **미리보기 473개 중 395개(84%)가 단 5개 문형에서 찍혀 나왔다.**

```
A 「…을 감수하고 …을 노린다. 실패하면 …이 남는다」        79회
B 「…을 무릅쓰는 대신 …을 챙긴다. …이 발목을 잡는다」     82회
C 「…를 먼저 잡고 빠진다. 다만 …와 …가 함께 남는다」      72회
D 「…가 필요하다면 …를 받아들인다. 그만큼 …이 따라온다」   87회
E 「…를 챙긴다. 대신 …가 생기고 …가 커진다」              75회
```

사용 횟수가 87/82/79/75/72로 고른 것은 효과와 무관하게 문형을 돌려 가며 채웠다는 뜻이다.

예:

| 이벤트 | 미리보기가 약속 | 실제 효과 |
|---|---|---|
| `EV_CH01_LOCKDOWN` | 신뢰 흔들림 | 오염 +2 |
| `EV_CH02_SUBMERGED_AMBUSH` | 지도 갱신·시간 초과 | 부상 +3, route.control |
| `EV_CH01_SECURITY_OFFICE` | 다음 레이드 부담 | 소음 +2 |

미리보기는 플레이어가 선택의 근거로 삼는 **유일한** 정보다. 여기가 거짓이면 선택지를 더 붙여도 밀도가 아니라 소음만 는다. **4-2보다 먼저 고친다.**

**고치는 방식:** 미리보기를 효과에서 생성한다. 그러면 구조적으로 거짓말이 불가능하다. 다만 5개 문형을 6번째 문형으로 대체하면 병이 재발하므로, 변주는 **효과 구성 자체**에서 나오게 한다 — 각 선택지가 바꾸는 자원의 조합이 이미 서로 다르다.

### 4-1b. 평판은 죽은 시스템이다

P1에서 `add_reputation`이 28번 실행된다. 그런데 **20개 챕터의 조건문·목표·엔딩 전체에서 평판을 읽는 곳이 0곳이다.** `rep.*`도 `reputation.*`도 참조되지 않는다.

부수적으로 키 공간이 둘로 갈라져 있다. `stats.registry`에 등록된 것은 `reputation.*` 6개뿐이고, 실제로 쓰이는 `rep.yeouido` `rep.noryangjin` `rep.jamsil` `rep.pangyo` `rep.magok`(13회)은 미등록이다. `rewards.ts:523`이 미등록 키도 그냥 만들어 쓰므로 오류 없이 조용히 쌓인다.

결정이 필요하다. **엔딩·상점·NPC 게이트 중 하나에 평판을 연결하거나, 미리보기에서 평판 약속을 걷어내거나** 둘 중 하나다. 지금처럼 두면 플레이어에게 아무 의미 없는 숫자를 계속 보여 주게 된다.

부수 결함: `trust.npc_han_sujin`은 NPC 레지스트리에도 스탯 키에도 없다. 한소명(`npc_han_somyeong`)의 오타로 보인다.
